# Игровой архив FNRI v1 (0.3.1.1)

Система поставляет Рулбук в штатных компендиумах. Отдельные игровые ZIP не входят в репозиторий и установочный архив. Импорт выполняется ведущим через Настройки системы → Игровой контент.

## Формат
`game.json` в корне ZIP: `format: "fnri-game"`, `schema: 1`, `system: "fast-nri-v14"`, `id` (slug), `title`, `documents` (Folder, Item, Actor, JournalEntry, Scene). Нативные документы Foundry VTT 14 со стабильными 16-символьными ID. Файлы WebP/PNG/JPEG в `assets/` или `assets/maps/`, `assets/portraits/`, `assets/tokens/`, `assets/illustrations/`. Внутри ZIP только файлы, без явных записей каталогов, исполняемого кода и произвольных путей. Ссылки `@asset/assets/...` заменяются на Data-пути `worlds/<world-id>/fnri-game/<archive-id>/<category>/<crc>-<filename>`. Категории создаются по необходимости. Лимиты v1: 128 МиБ, 32 МиБ на запись, 512 ZIP-записей, корневые папки документов.

Импорт идёт в порядке Folder → Item → Actor → JournalEntry → Scene. Существующий ID с той же меткой архива пропускается; конфликт с другим документом сообщает об ошибке. Не перезаписывает правки ведущего, не удаляет файлы. Сцены не активируются автоматически. Остальные документы закрыты для игроков по умолчанию, исключение — публичные карточки ролей. Ведущий назначает владельцев персонажей штатными правами. Использовать доверенные архивы. Не выполнять миграции.

## Роли внешнего игрового контента
Обычный мировой Item типа `item` с `system.mechanics.roleDefinition` = `{ "version": 1, "defenses": { "awareness": 0, "reflex": 0, "fortitude": 0, "will": 0 } }`. Только конечные числовые модификаторы этих четырёх характеристик. Изменяемые в листе Item; без иных механик. Карточка имеет штатное право Observer по умолчанию, чтобы участники видели один и тот же источник чисел. Не хранить в ней скрытые сведения и не закрывать её от игроков. Ссылка PC: `system.role = "world-role:<Item ID>"`; Item должен входить в тот же архив. В меню выбора отображается имя; изменение имени не разрывает ссылку. Смена/снятие роли пересчитывает производные значения без изменения исходных характеристик. Встроенный Наследник остаётся частью текущего Рулбука. Система не содержит имён, чисел, персонажей или артов внешних ролей.

## Проверка и выпуск
`bash tests/release-gate.sh`, `npm run check:packs`; `node tests/game-archive.mjs /path/to/private-game.zip` проверяет реальный внешний ZIP с заглушками API. Для установки требуется собрать штатные компендиумы (`npm install`, `npm run build:packs`) и упаковать систему существующим workflow. После публикации релиза на GitHub и штатного обновления системы проверить в Foundry VTT 14 загрузку файлов, выдачу ролей, переключение роли, повторный вход игрока, сохранение ID вложенных карточек и повторный импорт после изменения героя. GitHub не получает игровые ZIP или их содержимое. Не создавать release/v-ветку до явного решения о выпуске.


**Обязательный порядок релиза (ред. 178, 27.11.2026, прямое решение пользователя).** Пользователь получает обновления Foundry исключительно из GitHub через штатное обновление системы. Поэтому живая проверка в работающей Foundry VTT проводится **только после публикации обычного релиза**, не до неё. До выпуска обязательны технический аудит P01–P06, проверка согласованности документации, доступные автоматизированные тесты, компендии, сборка и проверка установочного ZIP и манифеста; выпуск — по разрешению пользователя. Открытая живая приёмка (`OPEN`) не блокирует технически готовый релиз и не превращает его в prerelease. После публикации пользователь обновляет систему, проверяет в игре и сообщает дефекты для следующего обновления. Не отмечать непроведённую проверку PASS. Обратная совместимость и миграции промежуточных версий до 1.0 не требуются. Это уточнение ред. 174 имеет приоритет над противоречащими историческими записями.
