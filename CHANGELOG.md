## v0.1.13 — исправления бросков, атак и карточек урона (20.11.2026)

- Исправлен переброс отдельного куба в редакторе ведущего: новый бросок через штатный `Roll`, результат «старое → новое» и сохранение исходного результата.
- В списках атак персонажей и существ отображается компактный профиль урона `A/B/+C`, включая выбранный вариант рукопашной атаки.
- «Вид атаки» сохранён как выпадающий список; свойство «Досягаемость» вычисляется для ближней атаки с положительной дистанцией без изменения исходного предмета.
- Самозащита учитывает независимые вид атаки, исходную проверку и используемую защитную характеристику. Поддерживаются особые правила и выбор Стойкости, Рефлекса или Воли, предоставленный способностью.
- Для бросков карточек добавлено свойство «Вмешательство»; оно блокирует запуск следующего Вмешательства из результата по умолчанию. Ведущий может переопределить его в конкретном сообщении.
- Исправлен поиск Actor выбранного токена при нанесении урона ведущим; отсутствие Actor не подменяется ошибкой прав.
- В карточке урона «Вмешательство» располагается сверху. При попадании показывается один итог `N`, основная кнопка «Нанести урон», справа «Крит». При критическом попадании — расчёт `N × M = K`, основная «Нанести критический урон», справа «Обычный». Обе нижние кнопки применяют HP, не переключая сам крит.
- Повторное применение не требует подтверждения. Каждое нанесение создаёт отдельный отчёт HP с собственным откатом. Подсвечиваются натуральные минимумы и максимумы результатов отдельных кубов.
- Контроль перед публикацией: `tests/release-gate.sh` и 9 Chromium-shim тестов. Реальная Foundry VTT 14 не проверялась.
- Известные ограничения: автоматическая интеграция всех произвольных защит и источников лечения, пассивных модификаторов крита из иных карточек и межклиентских гонок остаётся отдельной задачей.

## v0.1.13 — уточнение интерфейса карточки урона (локальный кандидат, 20.11.2026)

- В карточке урона кнопки **нанесения** доступны всегда, независимо от натурального критического результата. При обычном попадании главная «Нанести урон», маленькая справа «Крит»; при подтверждённом крите главная «Нанести критический урон», маленькая справа «Обычный». Кнопка «Вмешательство» остаётся отдельной строкой над ними.
- При обычной атаке показывается один итог `N`; при активном крите — один итог с верным расчётом, например `22 × 3 = 66`. Применение альтернативного варианта не переключает состояние крита в карточке, не перебрасывает кубы и не изменяет исходное сообщение.
- Повторное применение не спрашивает подтверждение, создаёт собственный отчёт HP с независимым откатом. Подсветка натурального минимума/максимума отдельных кубов сохранена.
- Добавлены проверки обеих кнопок и их порядка для обычного и критического результата. Локальная сборка; GitHub не затронут.

## v0.1.13 — локальный хотфикс интерфейса урона (20.11.2026, НЕ ОПУБЛИКОВАН)

- Убрано подтверждение повторного применения урона одной карточкой: каждый клик наносит выбранную сумму и создаёт самостоятельный отчёт HP с отдельным однократным откатом.
- «Крит» справа от «Нанести урон» теперь вторая **кнопка применения HP**, не переключатель. «Нанести урон» выбирает обычный расчёт, «Крит» — критический расчёт; исходная карточка и бросок при этом не изменяются.
- В карточке показаны два **уже вычисленных** числа: «Обычный урон: N» и «Критический урон (×M): K», а не неоднозначное «Итого: N ×M». Числа обновляются с учётом исключённых частей, штрафа, устойчивости, уязвимости и отмены Вмешательством.
- Натуральная 20 подсвечивает критический вариант; частная атака или способность может задавать `system.mechanics.attack.criticalThreshold` (1–20) и `criticalMultiplier` (более 1). Для рукопашных вариантов способностей — `system.mechanics.unarmedAttack.*`. Указанные поля доступны в редакторе соответствующего Item. Крит всегда считается после защит.
- В чат-результатах системы минимальные/максимальные значения отдельных кубов (1/число граней) подсвечиваются отдельно. В карточке урона фиксированные бонусы не имитируют кубы; исходные `Roll` не изменяются. Корректировка ведущим обновляет выделение частей.
- Сохранены права GM/владельца Actor, выбранный токен, независимые отчёты и отмена одной сохранённой дельты на отчёт.
- Добавлены адресные тесты обеих сумм, отдельного критического применения, отсутствия запроса на повтор, двух отчётов и двух откатов, порога 19/множителя ×3, подсветки min/max и сохранения старого сценария; `tests/release-gate.sh` и девять Chromium-shim тестов PASS.
- **Граница:** автоматическое чтение пассивных чужих способностей, которые изменяют крит *другой* атаки, ещё не реализовано; для прямой атаки способности и выбранной рукопашной способности работают поля собственной карточки. Живое тестирование Foundry 14 не выполнялось.

- Replace fixed numeric-only skill editor with unlimited skill/specialization rows sharing one addressable dictionary; free text dice expressions, no limits/presets forced.
- Preserve stage-2 legacy numeric row value separately; no automatic migration or reinterpretation.
- Allow any embedded Item in left/right hand or armor and add/delete arbitrarily many named equipment slots.
- Clear extra-slot Item references on explicit deletion, preserve missing external references with warning; no automatic gameplay effects.
- Prevent a failed Actor field update from silently losing unsaved changes on tab switch; add regression coverage.
- Expand source, local unit tests, RU/EN labels and template generator. No rules, roll logic or existing published data were changed.


### Исправления по аудиту (2026-11-16)

- Replace unpublished skill/resource arrays with keyed `TypedObjectField` for targeted partial updates.
- Replace competing Actor submit paths with a serialized field-level change handler and input validation.
- Move HP, combat die/attack modifier, speed, AC, defenses and resource summary to persistent Actor header.
- Preserve and visibly mark missing equipment references instead of silently clearing external deletions.
- Add optional manual wealth text field; no economy rules or automation.
- Make smoke tests version-agnostic; require explicit manual GitHub release workflow approval.
- No publication, no content import or migration, no game-rule changes.
